# tpt-reficon-core

Runtime support types for code generated by the
[`tpt-reficon`](https://crates.io/crates/tpt-reficon) proc macros.

Most users depend on the `tpt-reficon` facade, which re-exports everything
here. Depend on this crate directly only if you write generated code or
tooling that targets the runtime types without the macros.

## What it provides

- **`Refine`**, the trait implemented by `#[derive(Refine)]`. It has an
  associated `Inner` type and an `into_inner` method, which returns the raw
  value. There is no public constructor that skips the predicate: values are
  built through the generated `new` and `try_new`, which check it. Application
  code normally calls those generated methods, not the trait directly.
- **`RefinementError`**, the error returned by a failed runtime check. It is
  `Clone`, `Eq`, `Display`, and `std::error::Error`. It holds only a
  `&'static str` and never allocates. Its `Debug` output does not require the
  inner type to implement `Debug`.
- **`prelude`**, which re-exports `Refine` and `RefinementError`.
- **`fractional`** (feature `unstable`), a lock-free fractional-permission
  accessor for `u64` built on atomics. It uses no `unsafe`. See below.

## Example

```rust
use tpt_reficon_core::{Refine, RefinementError};

struct Bounded(u8);

impl Refine for Bounded {
    type Inner = u8;

    fn into_inner(self) -> u8 {
        self.0
    }
}

fn check(value: u8) -> Result<Bounded, RefinementError> {
    if value > 0 && value <= 100 {
        Ok(Bounded(value))
    } else {
        Err(RefinementError::with_message("`value > 0 && value <= 100` violated"))
    }
}
```

In practice the derive writes checks like this for you. Use
`RefinementError::new()` for a bare violation, or `with_message` for a
predicate-specific one.

## Feature flags

| Flag | Effect |
| --- | --- |
| `unstable` | Enables the `fractional` module (`SharedU64`, read and write handles). The API may change. |
| `verifier` | Pulls in `tpt-reficon-verifier` for solver-backed helpers used by macro-debugging tooling. |

## Design notes

**Fractional permissions (`unstable`).** A `SharedU64` holds a pool of
`WHOLE` units (`u32::MAX`). A reader takes one unit, and a writer takes the
whole pool. Handles return their units on drop. A writer must hold every unit,
so it can never coexist with a reader. Acquisition is a compare-and-swap loop
and never blocks. The same model is what
`tpt_reficon_verifier::permission::check_configuration` checks statically.

The accessor is limited to atomic-sized integers because the workspace forbids
`unsafe_code`. That restriction is deliberate.
